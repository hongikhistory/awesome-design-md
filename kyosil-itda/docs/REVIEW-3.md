# 교실잇다 3차 기능 심사위원 관점 검토

3차에서 추가한 네 도구(문서 변환, 수업 슬라이드, 가정통신문, 학생 상담·기록)를 사범대 웹콘텐츠 대회 심사 기준(교육적 필요성, 창의성, 완성도, 디자인·사용성, 확산 가능성)으로 다시 검토했다. 검토 대상은 커밋 `193456a`이다. 근거가 있는 지적만 담았고, 각 항목에 4차 조치를 적었다.

- 심각도: **상**은 감점이나 실격 우려가 있는 문제, **중**은 설득력을 떨어뜨리는 문제, **하**는 다듬을 문제.
- 측정 근거: `vite build`의 첫 로드 gzip 측정, 지도안 해석 코드 검토, 화면 캡처 검토.

## 1. 지적과 조치

| # | 지적 | 근거 | 심각도 | 4차 조치 |
|---|---|---|---|---|
| 1 | **생성 문서에 직인 모양을 찍는다.** 가정통신문 미리보기에 붉은 원형 ‘직인’이 그려진다. 심사위원은 공문서 직인을 흉내 낸 출력물을 위험 신호로 본다. | `Letters.tsx`의 `.stamp.paper-seal` | 상 | 점선 자리 표시 ‘(직인)’으로 바꾸고, 학교가 직접 찍도록 안내한다. 대신 학교 로고 이미지를 올릴 수 있게 한다. |
| 2 | **첫 로드가 두 배로 늘었다.** 2차판의 약 115 KB(gzip)가 232 KB가 됐다. 결강·대화방만 쓰는 교사도 문서 작성기(JSZip, markdown-it)를 미리 받는다. 2차에서 내세운 ‘가벼운 PWA’ 주장과 어긋난다. | `vite build` 로그 `first-load gzip ≈ 232 KB` | 상 | 네 도구 화면을 지연 로딩으로 분리한다. |
| 3 | **실제 지도안 표를 제대로 읽지 못한다.** 학교 지도안은 보통 ‘단계 / 학습 요소 / 교사 활동 / 학생 활동 / 시간 / 자료 및 유의점’ 열을 쓴다. 지금은 단계·시간을 뺀 모든 열을 합쳐 슬라이드 본문에 넣어 ‘※ 유의점’, ‘PPT 자료’ 같은 교사용 메모가 학생 화면에 나온다. | `lesson.ts` `readTable`: 나머지 열을 모두 `join` | 상 | 열 역할을 구분한다. 학생 활동을 우선하고, 자료 열은 준비물로, 유의점은 발표자 메모로 보낸다. 시험을 추가한다. |
| 4 | **도구가 따로 논다.** 협업 앱에 1인 도구 넷을 붙여 ‘도구 모음’처럼 보인다. 연결은 문서 변환 → 슬라이드·통신문뿐이고, 기존 협업(대화방·결재)과는 이어지지 않는다. 작품 정체성(‘교실을 잇다’)이 흐려진다. | 화면 흐름 검토 | 중 | 가정통신문 초안을 학년 협의방에 ‘검토 요청’으로 보내는 흐름을 넣어, 혼자 쓰는 문서도 동료 검토로 이어지게 한다. |
| 5 | **사람 냄새가 없는 화면.** 프로필은 색 원에 글자 한 자, 빈 화면은 회색 글뿐이고, 로고는 줄 세 개 아이콘이다. 실제 서비스라기보다 관리 도구 시안처럼 보여 첫인상 점수가 낮다. | 화면 캡처 | 중 | 브랜드 로고, 일러스트 프로필(사진 올리기 지원), 화면 일러스트, 절제된 애니메이션을 넣는다. |
| 6 | **슬라이드에 그림이 하나도 없다.** 미리캔버스·캔바 교육 템플릿과 나란히 놓으면 글자와 도형만 있어 밋밋하다. | 템플릿 5종 캡처 | 중 | 슬라이드 종류별 일러스트(전구, 연필, 사람들, 체크, 별)를 HTML 발표 파일과 PPTX 모두에 넣는다. |
| 7 | **‘AI 친화’라면서 AI 기능이 없다.** 심사위원은 “AI는 어디 있나”를 묻는다. | 문서 변환·생기부 화면 | 중 | 설계 의도로 설명한다. 학생·학교 정보를 외부 AI로 보내지 않고, 교사가 가리고 고른 내용만 복사해 넘긴다. 작품 설명에 이 원칙을 명시한다. |
| 8 | **학생 기록이 한 기기에만 있다.** 기기를 바꾸거나 브라우저 데이터를 지우면 누가기록·상담 기록이 사라진다. 백업 경로가 NEIS 엑셀과 상담 기록부뿐이다. | `Students.tsx` | 중 | 이번에는 한계로 명시한다. 운영판 계획: 담임의 다른 기기를 같은 방 구성원으로 등록하는 방식(키 봉인)으로 옮긴다. |
| 9 | **생기부 규칙의 근거 표시가 화면에서 약하다.** 31개 규칙 중 10개가 ‘원문 대조 필요’인데, 점검 결과에서는 작은 회색 칩으로만 보인다. | `records.ts` 확신도 집계 | 하 | 칩은 유지하고, 점검 영역 머리말에 ‘원문 대조 필요 n건’을 요약한다. |
| 10 | **한글 다운로드 파일명 미검증.** 테스트 브라우저에서 한글 파일명이 `download`로 받아졌다. 실제 Chrome·Edge·웨일에서 확인하지 않았다. | Playwright 실험 | 하 | 한계로 적고, 대회 전 실기기에서 확인한다. |

## 2. 그래도 강점인 것

- 학교 문서 형식(HWPX)을 서버 없이 브라우저에서 읽고 쓰며, 학교 양식의 서식을 지키며 빈칸을 채운다. 국내 교사용 웹 도구에서 드문 기능이다.
- 생기부 점검이 학년도별 글자 수 한도와 규칙마다 근거의 확실성을 함께 보여 준다. ‘AI가 다 써 준다’가 아니라 교사의 판단을 돕는 방향이 2026학년도 기재요령과 맞는다.
- 슬라이드가 HTML 발표 파일(글꼴 포함, 활동 타이머)로 나와 학교 PC의 글꼴 환경과 무관하다.

## 3. 이번에 하지 않은 것

- 다른 기기로 학생 기록 옮기기(8번): 키 봉인 구조는 있으나 기기 등록 화면이 필요하다.
- 실제 학교 HWP 5.x 지도안·통신문 샘플로 시험하기: 공개 샘플을 구하지 못했다.

## 4. 4차 조치 결과

| # | 결과 |
|---|---|
| 1 | 직인 그림을 없앴다. ‘(직인)’ 자리 표시나 직인 생략 중에 고른다. 학교 로고는 ‘학교·내 정보’에서 올린다. |
| 2 | 네 도구를 지연 로딩으로 분리했다. 첫 로드는 232 KB에서 128 KB(gzip)로 줄었다. 도구 화면을 불러오지 못하면 안내를 띄우고 앱은 계속 동작한다. |
| 3 | 열 역할을 인식한다(학생 활동은 슬라이드, 교사 활동·유의점은 발표자 메모, 자료는 준비물). 성취기준 코드와 ▣·★·※ 기호도 읽는다. 시험 2개를 추가했다. |
| 4 | 가정통신문의 ‘학년 협의방에 검토 요청’이 종단간 암호화 대화방으로 이어진다. |
| 5 | 로고, 그림 프로필(사진 올리기 지원), 오늘 화면 일러스트, 빈 화면 그림, 절제된 애니메이션을 넣었다. 움직임 줄이기 설정을 켜면 애니메이션이 모두 꺼진다. |
| 6 | 슬라이드에 직접 그린 아이콘을 넣었다. 미리보기, HTML 발표 파일, PPTX(브라우저에서 PNG로 변환) 모두에 들어간다. |
| 7 | AI용 복사는 개인정보를 기본으로 가리고, 생기부 요청문은 학생·같은 반 학생·학교·전화번호를 가명으로 바꾼다. |
| 8 | 학생 기록에 암호 백업·복원(PBKDF2 600,000회 + AES-256-GCM)과 ‘빈 학급으로 시작’을 넣었다. 저장 공간이 지워지지 않게 요청하는 버튼도 넣었다. |
| 9 | 점검 머리말에 ‘원문 대조 필요·관례 n건’을 요약한다. |
| 10 | 미해결. 실기기에서 확인해야 한다. |
